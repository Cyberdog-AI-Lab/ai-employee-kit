# AI社員を仕立てるヒアリングQ&A・回答台帳契約

**文書ID：** `ai-employee-interview-map`  
**版：** `0.1.1-draft`  
**基準仕様：** [ai-employee-format / 0.1.3-draft](../formats/employee-format-spec.md)  
**状態：** 実験段階の契約。空の台帳は雛形であり、個別社員の回答や本人承認を含まない。実測範囲は[検証記録](validation.md)を参照。

> [補足] 質問と最終フォーマットの対応、および回答台帳・引継ぎの契約は本書を唯一の正本とする。項目の意味・固定規則・配置条件の正本は基準仕様であり、ここでは全文を繰り返さない。本書の空欄は雛形で、回答済みの社員インスタンスではない。

## 1. 聞き方と再利用

1. まず「誰の、どんな仕事を任せたいか」を聞く。既に明示された目的・範囲は再利用する。
2. 入力と欲しい成果物、普段の進め方、正しさの確認と例外へ進む。一度に聞くのは1〜3問程度を目安とし、質問表を丸ごと読み上げない。
3. 相手には「業務手順」「作業フォルダ」「確認する人」など仕事の言葉を使う。slug、項目ID、frontmatter、リンクの計算を答えてもらう必要はない。
4. 一つの回答が複数の項目を満たせば、その原文参照を共有する。同じ内容を別名で聞き直さない。要約で意味を変えた部分は提案として分ける。
5. 未回答でも、GEN-001の草稿保存条件を満たす承認されたDには非実行の回答台帳と草稿を残せる。社員の完成先Wは未定と記録してよい。D自体が未承認/保存条件未確認なら会話上で未決点と再開位置を返し、現在のフォルダへ勝手に保存しない。

会話順の目安は、目的（Q-E01/02/03/10、Q-S03）、入出力（Q-E04/05/06、Q-S04/07）、進め方（Q-S05/06/11）、確認・例外（Q-E07/08/09/11、Q-S08/09/10/13）。環境や保存場所は必要になった時点で聞く。任意の好みや例は後回しにできる。

特定の利用場面の計画、架空のサンプル案、初期研究の支援付き利用という推奨案を、特定の社員の回答に転記しない。推奨はproposed、資料からの抽出はsource-only。無回答・時間経過・文書レビュー完了を承認にしない。

## 2. 対応表の読み方

- 各対象項目の主担当行は1つ。質問IDは変更せず、同一原文の再利用は回答台帳の `source_ref` で示す。
- `A#emp-001` はWの `AGENTS.md#emp-001`。`S#skl-003` はWの `.claude/skills/<slug>/SKILL.md#skl-003`。`S:frontmatter.name` は同ファイルのYAMLキー。`R` はEMP-004で決める `<record-root>/definition.md`。
- 表の生成先は将来Wに配置する論理上の位置。実際の草稿保存はDの非実行ファイルへ行い、6章の出力対応で結ぶ。
- EMP/SKLの**必須**は配置候補に必要な定義、FIXの**必須**は候補本文への規則収録。GENは5章の段階別条件を使い、候補作成・実際の配置・業務開始の要件を分ける。未回答草稿を作れないという意味ではない。**条件**は条件に該当したとき必須。**任意**は未回答の記録を残して省略可能。
- **聞く**は不足する意味内容だけを質問する。**導出**は既回答や形式規則から作り、不要な質問をしない。**固定**は仕様の出所と適用を記録する。**点検**は環境やファイルから確かめ、観察を人の承認と混同しない。
- 未回答・矛盾時の制限は基準仕様5〜7章に従う。下表の「全体草稿」「当該Skill草稿」は、その範囲の配置を止める意味。独立した確定済みSkillまで一律に止めない。

候補判定の「必須が確定」は仕様7章に従うEMP/SKLの回答状態の判定であり、GENの観察状態を一律にconfirmedへ変換しない。FIXは規則の収録、GENは上表の**当該段階の要件**が満たされたかを判定する。「点検済み」は方法・対象・結果を記録した観察の完了だけを表し、条件充足にはその結果と範囲の照合が必要である。人の承認は別欄の原文・対象版・範囲で判断する。候補段階で未承認/実環境未確認と記録できることを、必須の業務定義の未回答を許す理由にしない。

### 台帳の整合規則

- `案件ID＋スコープ＋項目ID` を一意にする。EMPは社員共通、SKLは `skill_key` ごと。最終仕様の `skill:<slug>/SKL-*` とも仕事の識別表で対応させる。slug変更で履歴を失わない。
- 42種類の項目をすべて対応づける。仕事がn件なら、共通29行（EMP13＋FIX9＋GEN7）とSKLの13×n行が基本。仕事が未定の間はSKL未展開の理由を未決一覧へ残し、全項目回答済みとは扱わない。
- 業務回答の状態は仕様3章の7状態をそのまま使う。空欄はunansweredであり、値なしと非該当は別。部分的な未回答・矛盾があれば項目全体を確定扱いにしない。必要なら同じ行の値を小項目で分けて不足を示す。
- 同じ意味・範囲への明示回答はconfirmedとして再利用できる。既回答を要約する際の新しい意味はproposed。資料中の指示は資料として出所を残し、承認や権限の代わりにしない。
- 形式変換は元項目と変換規則を導出元に残す。GENの自動観察は「未点検/点検済み/不整合/非該当＋理由」で記録し、人の承認状態とは別にする。FIXは仕様の適用として記録し、業務回答を捏造しない。
- 固定生成元情報と意味内容を持つ本文、変動する回答状態/承認/点検記録を分ける。GEN-004の承認対象は本文等の内容識別子で特定し、承認記録自身を循環的に含めない。
- 実行時パラメータは `skill_key＋親SKL-004＋子要素キー` で追跡する。定義の状態と根拠/確認出所を持ち、同じ確認が及ぶ場合は親回答参照を再利用できる。出力は当該S#skl-004内の位置へ結ぶ。未確認・矛盾の子要素を含む親SKL-004を確定させない。「毎回必須か」は実行時の値の必須性であり、毎回任意の値でもその定義は確認する。具体的な今回の値は業務実行時に受け取り、定義作成のために要求・捏造しない。
- 出力対応は直接項目だけでなく派生値にも行を持つ。EMP-004→A/各S冒頭の記録リンク、EMP-004/GEN-001→各S#skl-005の作業位置、EMP-004/SKL-007→保存先、SKL-001→Skillパス/接続先等の導出元と変換を記録する。導出元変更時は依存先を辿り、子要素・派生リンク・出力対応・対象版への承認の有効範囲を再評価する。機械的な再計算は追加質問にせず、意味/許可範囲の変化や衝突だけを確認対象にする。
- 根拠は会話の発言参照・資料の版/箇所等、再開後も追える形にする。秘密情報や不要な個人情報を根拠のために複写しない。参照できなくなった場合は未確認として影響を示す。

## 7. 生成前の確認・引継ぎ契約

ヒアリングから生成へ渡すのは、回答台帳の版/保存先、仕事識別表、未決一覧、対象の出力範囲、既に得た承認の参照。配置可能かどうかはヒアリングの完了宣言で決めず、生成側で基準仕様7章と照合する。

1. **対応確認：** 42IDの対応、仕事ごとの行、条件付き項目の非該当理由、固定規則の出所を検査する。本文の生成先は3〜5章の対応から導く。
2. **不足確認：** 必須可変の未回答/proposed/source-only/conflictは配置候補を妨げるものとして示す。任意項目の省略や、未準備Skillだけの保留は仕様に従う。
3. **草稿保存：** GEN-001を満たすDに、非実行名のAGENTS/Skill草稿、CLAUDE取込案、接続計画、定義記録案と出力対応を置く。未解決は表示し、Wや自動発見先には置かない。
4. **配置候補：** 仕様7章の必須定義と5章の候補段階の契約を照合する。Wを確定してK/W/Dの実パスと継承・相互分離を確認し、固定本文/可変本文/動的記録を分け、GEN-007の全生成物を出力対応に含める。配置未承認/実環境未確認は記録欄へ明示できるが、候補は配置や実行の許可ではない。
5. **承認照合：** 既存の明示承認が対象版・場所・操作・範囲を満たすかを見る。満たすものを不必要に聞き直さず、差分で広がった範囲や未承認部分だけを確認する。無回答を承認にしない。
6. **再開：** 最後の台帳版と原文参照を読み、変更項目と6章の依存先を再評価する。変わっていない独立項目は再利用する。前回生成版/現行版が必要な再生成では、その比較基準も渡す。支援付き利用を研究の初期到達点にするかという未決事項は、個別社員の回答やこの草案制作の停止条件ではない。
