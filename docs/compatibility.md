# Codex / Claude Codeの共用構成

このキットは同じ指示とSkillを両ツールへ接続する構成です。ファイルが揃うことと、実際の発見・読み込み・業務成功は分けて確認します。実測範囲は[検証記録](validation.md)を参照してください。

| 対象 | 正本 | 接続 |
| --- | --- | --- |
| 共通指示 | AGENTS.md | CLAUDE.mdで `@AGENTS.md` を取り込む |
| Skill | .claude/skills/<name>/SKILL.md | .agents/skills/<name>から相対リンク |

リンク先は `../../.claude/skills/<name>` です。Markdown参照は正本Skillの実ディレクトリを基準にします。キットrootで作業する場合と生成社員workspaceで作業する場合を混同しません。上位フォルダやアカウントの指示も確認してください。

## リンクが使えない場合

1. `.agents/skills/<name>` の状態を確認します。リンク、実ディレクトリ、リンク文字列だけの通常ファイルを区別します。
2. 既存内容を保持して移動先を空け、`.claude/skills/<name>/` を `.agents/skills/<name>/` へコピーします。既存フォルダの中へ重ねて二重階層にしません。
3. 両方のSKILL.mdと付属ファイルの内容が一致することを確認します。コピー先を独立編集せず、正本更新ごとに同期します。

OSごとのリンク作成権限や、各ツールが読む指示のサイズ・範囲は実環境で確認してください。AGENTSには共通方針を簡潔に置き、長い手順はSkillや参照資料に分けます。Windowsでの導入や全環境での動作は今回の試験に含めていません。

## Codexが読むファイルと範囲

2026-10-16に確認した公式の[AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)と[Build skills](https://learn.chatgpt.com/docs/build-skills)に基づきます。

- AGENTSはプロジェクトrootからcwdまでの経路で読まれます。同じ場所のAGENTS.override.mdが優先され、既定の総量上限は32KiBです。別名を認識させる個人設定には依存しません。
- Skillはcwdからリポジトリrootまでの `.agents/skills` が探索されます。`<slug>/SKILL.md` の先頭YAMLにname/descriptionが必要です。同じW内の正本へのsymlinkは公式に対応しています。
- descriptionが選択の手がかりであり、本文の読込みは選択後です。Codex CLI/IDEでは `/skills` または `$<name>` で指定でき、通常の自動選択も可能です。アプリのUIは利用中の版に従い、CLIでの確認をアプリ画面確認に置き換えません。
- `agents/openai.yaml` は任意です。今回の修正で自動選択を無効にはしません。

## 配置後の検査

Python 3.10以上の環境に `scripts/requirements-validation.txt` の依存（PyYAML）を用意し、次を実行します。検査器・コピー補助・両回帰テストの最低版はPython 3.10です（テスト記録の `sys.orig_argv` 等を使用）。今回の実行環境はPython 3.11.5 / PyYAML 6.0.1で、最低版や他OSでの実行確認とは分けます。検査は読取りのみで、権限・業務判断・人の検収を保証しません。

```sh
python3 scripts/verify_employee_workspace.py /path/to/employee --kit-root /path/to/ai-employee-kit
```

この検査の範囲と結果は次のとおりです。

- `AGENTS.md`、`CLAUDE.md`、`.agents`、`.claude`、`skills`、`SKILL.md` は、実際の親ディレクトリのエントリ名と大小文字まで一致させます。ローカル依存パスとsymlinkの解決先も同じ方法で点検します。
- `.agents`、`.agents/skills`、`.claude`、`.claude/skills` の4コンテナは実ディレクトリに限定します。W内を指す相対symlinkでもコンテナの代用にはできません。
- GEN-007の接続symlinkは、リンク文字列が `../../.claude/skills/<slug>` と完全一致する必要があります。同じ正本を指す絶対リンクや、同じ内容でも別の場所を指すリンクは不合格です。壊れたリンク、W外への参照、循環も検出します。コピー方式では付属資料も含めてファイル内容を照合します。
- W全体の実ディレクトリを列挙し、Markdownから未到達の場所を含めたsymlinkを `symlink_audit` に記録します。AGENTS/CLAUDE・依存資料を含むどの場所でも絶対リンクは不合格です。ディレクトリsymlinkには降りず、相対リンクの各経路要素をW内で解決し、W外への移動を解決前に拒否します。リンク先の本文をW外から読まず、全Wの本文をハッシュするものでもありません。読取り専用の静的検査であり、検査中の同時書換えを防ぐアクセス制御ではありません。
- YAML、nameとフォルダ名、空白だけのdescription、未展開記号、単体AGENTSの32KiB超過を確認します。バッククォート・チルダの外側フェンスと、既知の説明用テンプレート文言を伴う囲みを検出します。フェンス検査はヒューリスティックであり、すべての説明文を意味判定するものではありません。稼働本文の中のコード例は許容します。
- `kit_workspace_separation` に `status: checked / not_checked`、`passed: true / false / null`、確認したKの実パスを記録します。`--kit-root` 省略時は `not_checked` / `null` と警告を残し、`all_passed: false`・終了コード1にします。その場合でも、実施した静的検査の成否は `static_checks_passed` で確認できます。配置後の点検では引数を省略しません。指定Kが存在しない・ディレクトリでない場合も不合格です。
- `all_passed: true` は、K/Wの実パス分離を含む、このスクリプトが実施した静的検査だけの合格です。Dとの分離、上位・アカウントの指示継承、承認、実際のツール認識、業務結果、人の検収を確認した意味ではありません。

依存リンクは、AGENTS・CLAUDE・正本/接続のSKILLとSkill付属ファイルから、次のMarkdown部分集合で再帰的にたどります。リンクされたディレクトリ内も走査します。

- 単一行の `[label](relative/path)` と画像リンク、`[label](<space in path.md>)`、引用符付きタイトル、URLエンコードされたパス、1段の丸括弧を含むパスに対応します。
- 単一行の参照定義 `[id]: <path> "title"` を使う `[label][id]`、`[id][]`、定義済みの `[id]` に対応します。2組の角括弧は隣接する必要があります。空白やタブで区切る `[a] [b]` は、定義がなければ通常の文章です。定義がある角括弧だけは独立した短縮参照として扱います。参照ラベルは空白を正規化し、大小文字を区別しません。隣接した未定義の明示参照はエラーとし、使われない定義はたどりません。
- 箇条書きのマーカー行でもリンクを検査します。対応マーカーは `-` / `+` / `*`、1〜9桁の数字に `.` または `)`、直後に1〜4個の空白です。タブは4列のタブ位置に展開します。最上位マーカーは0〜3列の字下げ、入れ子は有効な親項目の本文開始位置から0〜3列の字下げで認識します。空行は親項目の状態を保持し、後続のマーカーなし本文も同じ0〜3列で検査します。親がなければ4列以上、親があればその本文開始位置からさらに4列以上の行はコード例として除外します。このため `    - [example](missing.md)` は親リストなしではコード例です。
- ローカルの `.md` / `.markdown` は再帰検査し、循環した参照は再走査しません。上記字下げ規則に従うコード、トップレベルおよび認識したリスト内のフェンス、インラインコード、HTMLコメント内の例示リンクはたどりません。`file:` URI・絶対ローカルパスは不合格とし、その他のURIは取得せず、未確認と警告します。
- `configuration_sha256` は設定ファイル、`reachable_local_file_sha256` は上記の走査で到達した設定・資料・画像等のローカルファイルをSHA-256で記録します。後者には接続側と実体側のパスも含まれます。失敗した検査のハッシュ一覧は部分的な記録です。Skill一覧・ディレクトリ走査・コピー比較で無視するのは通常ファイルの `.DS_Store` だけで、その他の隠しファイルや `.DS_Store` というsymlinkは検査します。

これは完全なMarkdown解析ではありません。複雑な入れ子ラベル、複数行のリンク/参照定義、HTML属性、裸の `<local-path>`、埋込みやプログラム中のパスは対象外です。リストの遅延継続（lazy continuation）、マーカー後5空白以上、引用ブロックとリスト/フェンスの組合せ、セットエクスト見出しや区切り線との文脈判定は実装していません。これらではリンクの見落としやコード例の誤検出があり得ます。空行なしで段落直後に字下げした行も上記の列数だけでコード扱いするため、CommonMarkの段落継続判定とは異なります。曖昧な依存は対応範囲の独立したリンク行へ書き直すか別途確認してください。アンカーの存在、URI先の内容、ファイル内容の正しさも検証しません。静的検査だけで全依存の網羅・実行時の発見や読み込みを保証しません。

`prepare_sample_workspace.py` のスナップショットも、各階層の通常ファイルかつ非symlinkの `.DS_Store` だけをハウスキーピングとして除外します。コピー自体はこれらも保持し、コピー受領記録に「コピーするがハッシュ対象外」と明記します。`.DS_Store` というsymlinkは必ずリンクとして検査・記録し、同名ディレクトリの内容や他の隠しファイルは除外しません。`bundle-manifest.json` 自身は既存のスナップショット仕様どおりファイルハッシュ一覧から除外し、コピー受領記録で別途SHAを記録します。`copy_content_matches` はこの除外規則の下での一致であり、コピー後の受領記録自身や除外ファイルまでの全バイト一致を意味しません。

新しい会話はWを開いて開始し、「現在適用されている担当・制約と利用可能な業務Skill」を確認します。単にファイルを表示して読ませる確認とは区別してください。Skill一覧の選択可否、実際のSKILL.md読込み、入力からの実行結果は別に残します。

## 検査スクリプトの回帰テスト

PyYAMLを用意したPython 3.10以上で、キットrootから実行します。

```sh
python3 -I -B scripts/verify_samples.py
python3 -I -B scripts/test_employee_workspace.py
python3 -I -B scripts/test_prepare_sample_workspace.py
python3 -I -B scripts/test_samples.py
```

各コマンドは `--output <保存先.json>` で結果を保存できます。3つのtestスクリプトはOSの一時ディレクトリに架空の検査用コピーを作成し、終了時に削除します。必要なら `--temp-root <KIT外の一時保存先>` を指定します。通常の社員workspaceや生成済みの成果物は変更しません。

配置検査は正規名・YAML・大小文字・相対リンク・外部参照・依存文書を、コピー検査は原本保持・保存先分離・改変・リンク循環・旧階層へのフォールバック拒否を確認します。配布検査は各社員内に設定・入力・ヒアリング・出力が完結すること、Skill配下の参照資料を含む定義と、独立照合記録のhashが実行に結び付くことを確認します。回帰は `assert` に依存せず、Pythonの最適化モードでも検査します。

これらは保存済み構成とファイルの検査です。Codex本体の認識、業務再実行、人の検収とは分けます。実施した範囲は [検証記録](validation.md) にあります。

## 収録サンプル

`sample/sales/`・`sample/minutes/`・`sample/reconciliation/` が、それぞれ社員workspaceそのものです。[社員一覧](../sample/README.md)からヒアリング、設定、入力、成果物、記録を確認できます。社員フォルダ全体をK外へコピーして使います。`.agents` / `.claude` の隠しディレクトリと相対リンクも含めてください。生成時の確認と、コピー先での認識・実行は別に記録します。
