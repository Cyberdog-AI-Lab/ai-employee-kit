# 検証記録

2026-10-15時点の実測範囲です。実験段階の公開版であり、AIの自己検査、取りまとめ担当による独立照合、Claude Codeによる別担当レビュー、人の確認を分けています。

## 環境と方法

- macOS上の独立した仕事フォルダを使い、Codex CLI 0.159.2で聞き取り・生成・業務試験を実施。業務は各社員フォルダを開いた新しい会話で行いました。デスクトップGUIでの実演は今回の検証に含めていません。
- 生成元仕様は0.1.3-draft（最初の売上生成では0.1.2-draft）、Q&A自体は0.1.1-draft。公開版には文脈整理と試験条件の明確化も加えています。元生成時と公開後の内容識別子は同一とは扱いません。
- 仕事の入力は全て架空。模擬回答はAIによるもので、通常のconfirmedや人の承認へ変換していません。実際の試験許可は別にあり、試験専用Wへの配置・実行として記録しています。
- 業務処理の補助コードはPython 3.11.5の標準ライブラリを使用。ブラウザ、MCP、メール送信、外部資源の取得は業務処理では使用していません。AIサービスとの通信を遮断した試験ではありません。
- 売上・議事録の期待値は実装・実行前に別管理し、実行担当には提示せず、保存済み成果物と別に照合しました。売上は別のSQLite集計でも事前値を点検しました。商品紹介の期待値は入力事実そのもので、入力として実行担当にも見えています。機械検査はその保持と参照構造を確認し、紹介文の意味が入力の範囲に収まるかは取りまとめ担当AIと別担当Claude Codeが読んで確認しました。人の検収ではありません。

## 失敗と修正

最初の売上手順は期間不足で止まりましたが、開始前の停止記録を保存しませんでした。Claude Codeの独立レビューで、必須条件の確認と記録作成の順序を見直しました。テンプレート・生成手順・社員手順を修正し、新しい会話で停止記録→回答→別runの再開を確認しました。

最初の模擬回答には、試験内の状態をconfirmedで表すよう取りまとめ側が指定した問題もありました。その指示と旧版を残したうえで、通常の回答状態と試験条件を分離し、模擬回答を本人の承認に見せないよう修正しました。

売上再試験の補助コード準備コマンドは、余分なトークンにより一度失敗しました。実行担当はエラーを記録し、生成済みコードの構文を確認した後に実行しました。これを最初から無失敗だったとは扱いません。

商品紹介の初回最終検査では、Markdownの文字参照（例：&#95;）を復号せずJSONの文字列と比較し、自己検査表の照合が失敗しました。[失敗記録](../sample/product/validation/failed-finish-record.json)と旧成果物を保持し、別runで検査側の表示復号・表の比較を修正しました。原稿本文と生成処理は実行ID以外に変更がなく、再検査を通過しました。失敗した初回成果物を検収待ちの成功として採用していません。

## 検証していないこと

- 人による定義内容のレビュー、成果物の検収、非技術者の使いやすさ・必要支援量・作業時間の改善。
- Claude Codeで同じ3業務を実行したときの結果。今回Claude Codeが担ったのは独立レビューです。
- Windowsやリンクを使わないコピー方式、Excel形式そのもの、大容量資料、実顧客データ、継続運用、あらゆる不正入力への対応。
- HTMLのブラウザでの目視確認。3つのSVG・数値・静的な外部資源不使用は点検しました。
- OSやアカウント全体でのアクセス制御・外部通信遮断の保証。指示ファイルは技術的な権限制御の代わりにはなりません。
