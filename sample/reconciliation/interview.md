# 請求・入金照合担当 — 現行ヒアリング

AIが架空の担当者を演じた回答を、現行条件として整理した記録です。意味回答はすべて **proposed（模擬条件）**、通常confirmedは0、人による定義承認・成果検収は未実施です。質問文は読みやすく整理しており、当時の発言の逐語録ではありません。原文・42項目の対応・確認出所は [Gitに保存した回答台帳](https://github.com/Cyberdog-AI-Lab/ai-employee-kit/blob/8ed9ba51a3bf66ab8f8a009e6fbc3551b23394c1/sample/reconciliation/records/answers.runtime-v001.json) で確認できます。

## 誰の、何の仕事か（EMP-001〜003 / SKL-002〜003）

**問い：誰が何を判断できるようにしますか？**

架空の経理担当の毎日の入金確認を助ける。請求と入金をルールに沿って照合し、未回収・未割当・確認事項の根拠と次に見る順序を示す。会計システムの消込は行わない。

依頼者、成果の検収者、定義変更の確認者、保守担当は [AGENTSの役割設定](AGENTS.md#emp-003) に従います。模擬の役割設定を、実際の人が確認した記録にはしません。

## 入力と実行条件（EMP-004〜005 / SKL-004）

**問い：どの資料を使い、毎回何を指定しますか？**

[inputsの架空原本](inputs/README.md) を読取り専用で扱います。入力一式はfixture_revision=v3。次は同梱した最新成果の実行値で、次回の既定値ではありません。新しい依頼で値を明示します。

| パラメータ | 同梱成果の実行値 |
| --- | --- |
| `input_dir` | `inputs` |
| `dataset_id` | `AR-DEMO-2026` |
| `as_of` | `2026-10-15` |

型・検証・不足時の扱いは [Skillの入力条件](.claude/skills/work-001/SKILL.md#skl-004) に従います。日付やIDを入力ファイル・PCの時計から補いません。

## 判断のルール（SKL-006 / SKL-011）

**問い：どこまで自動で判断し、何を推測しませんか？**

[照合ルールR01〜R11](inputs/matching-rules.md) を全文適用する。名義の別名・手数料契約は顧客名簿に明示されたものだけを使う。単独明示ID、完全合算、一部入金、IDなしの一意一致を所定の条件で評価し、競合や超過を先着順で割り当てない。

手数料330円の許容には単独明示ID・名義・契約・有効期間等の全条件が必要。差額候補は参考表示に留め、割当や会計判断にしない。基準日後の入金は別掲。ルール照合済み、要確認、未入金と、未回収・未割当を区別する。詳細は [Skillの判断手順](.claude/skills/work-001/SKILL.md#skl-006) に残す。

## 成果物と確認（EMP-006〜007・013 / SKL-007〜009）

**問い：何を渡し、何を確かめますか？**

単体HTML・JSON を `outputs/<新しいrun-id>/` に保存します。要点・次に確認する事項を先に、日本語で示し、根拠原文・行・IDへ辿れるようにします。入力の前後hash、対象と除外の網羅、形式間の値の一致、業務ごとの検算を確認します。自己検査と人の検収を分け、`human_acceptance: false` を保持します。詳細は [検査手順](.claude/skills/work-001/SKILL.md#skl-008)。

## 停止と操作範囲（EMP-008〜009・012 / SKL-005・010・013）

**問い：何が足りなければ止め、どこへ保存できますか？**

必要ファイル/ヘッダー欠落、manifest不一致、原本保護不能、保存先不明、検算破綻なら全体停止する。行不正や曖昧な名義は関係する候補・割当を保留する。 必須パラメータ不足・原本保護不能・既存成果の置換が必要な場合も停止します。質問前に新しい `records/runs/<run-id>/` へ理由・未処理・再開条件を記録し、書けなければ会話へ残します。

今回の依頼に必要な入力・定義の読取り、新しいoutputs・実行記録・必要な処理コードの保存に限定します。原本変更、既存成果の置換、外部送信、新規連携・導入・権限拡張は含めません。利用可能なローカル道具と実権限を、その都度確認します。MCPは必須ではありません。

## 引継ぎと未決（EMP-010〜011 / SKL-001・012）

**問い：どの手順を使い、改善をどう残しますか？**

仕事のslugは形式上の固定値 `work-001`。指摘・理由・差分・影響を残し、依頼された範囲で改訂します。過去の定義はGit履歴から回復できます。業務意味はruntime-v001を継承し、今回の整理は保存先と根拠参照の変更です。任意のSKL-012は未回答のままです。実環境の操作権限・次回の実行依頼・人の検収は、新しい利用時に別途確認する事項です。
