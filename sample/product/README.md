# 商品紹介担当の試験

[インタビュー](interview.md)で不明値や矛盾の扱いを聞き取り、キット外へ試験配置した社員を、新しいCodex会話で実行しました。架空の役割と資料を使う試験であり、人の候補レビュー・成果検収は未実施です。

## 実行結果

資料IDが未指定の依頼では、入力からIDを補完せず、停止理由と再開条件を保存しました。その時点ではoutputsはありませんでした。ID回答後は停止記録を参照した新しいrunで処理し、旧記録と入力を保持しました。

2商品の名前・内容量・仕様・unknownsを保持しました。P001の価格は800円、P002の価格はnullです。紹介文は入力にある内容量と特徴だけから作り、入力フィールドへ各主張の根拠を結びました。電子レンジ・食洗機対応を肯定も否定もしていません。

入力事実を保持する期待値との照合、根拠との対応、入力の前後ハッシュ、停止・再開の記録を確認しました。商品紹介の期待値は入力事実そのもので、入力として実行担当にも見えています。機械検査はその保持と参照構造を確認し、紹介文の意味が入力の範囲に収まるかは取りまとめ担当AIと別担当Claude Codeが読んで確認しました。人の検収ではありません。AIの自己検査済みと人の検収待ちは別の状態です。

商品紹介の初回最終検査では、Markdownの文字参照（例：&#95;）を復号せずJSONの文字列と比較し、自己検査表の照合が失敗しました。[失敗記録](validation/failed-finish-record.json)と旧成果物を保持し、別runで検査側の表示復号・表の比較を修正しました。原稿本文と生成処理は実行ID以外に変更がなく、再検査を通過しました。失敗した初回成果物を検収待ちの成功として採用していません。

## 参照資料としての制約

[provenance.json](provenance.json)で試験原本と公開用複製を区別しています。定義は非実行名で、ローカルパスは匿名化しました。このフォルダをそのまま稼働させず、インタビューと入力例をもとに自分の作業場所へ再生成してください。
