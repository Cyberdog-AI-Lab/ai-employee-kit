## 共通方針

<a id="skl-003"></a>
## 適用・非適用

こもれび商店の架空入力から売上照合・可視化を明示的に依頼されたときに使う。販売・返品・マスタ・表記ゆれ・価格改訂・店舗メモを対象とする。原因推測、施策断定、税再計算、実業務利用、会計更新、第三者送信・公開には適用しない。境界が曖昧なら依頼元（架空の店長の確認役）へ問い合わせる。

適用が曖昧な場合は業務条件を確認し、便利そうという理由だけで対象外の仕事へ広げない。

<a id="skl-004"></a>
## 入力と実行時パラメータ

値は毎回の業務依頼から受領する。入力ファイルの月や過去の実行値から期間を推定しない。

| パラメータ | 型・単位 | 必須性 | 入手・検証 |
| --- | --- | --- | --- |
| input_dir | パス文字列 | 毎回必須 | 依頼から受領し、この社員workspaceの inputs/ と実パスが一致すること。配下のファイルとsymlinkも同範囲内で読取り可能であること。 |
| start_date | ISO日付 YYYY-MM-DD | 毎回必須 | 依頼から受領。実在する暦日で、start_date <= end_date。開始日を含む。 |
| end_date | ISO日付 YYYY-MM-DD | 毎回必須 | 依頼から受領。実在する暦日で、start_date <= end_date。終了日を含む。 |

いずれかが不足/不正なら開始前に停止し、SKL-010の停止記録を残してから確認する。業務出力ディレクトリはまだ作らない。

入力の具体的パス、列、型、単位は [入力構造](references/input-schema.md) を参照する。販売は `transaction_id,date,store_label,product_label,quantity,unit_price_jpy,discount_jpy,channel`、返品は `return_id,original_transaction_id,return_date,quantity,refund_jpy,reason`。金額は整数円、数量は個数として原値を保持する。マスタ・明示別名だけでIDを対応づける。欠損、不正数値、重複、矛盾の扱いは [判断規則](references/sales-rules.md) に従う。

入力の形式、必要項目、今回の期間・単位・対象を確認する。欠損・重複・矛盾が判断に影響し、処理方針が未定ならその結果を確定しない。不明として出力することが確認済みの手順で認められる場合は、その範囲を明示する。

業務の作業ディレクトリと、Skillの参照資料の基準ディレクトリを区別する。必要な入力、ツール、権限、参照先が使えるかを確認し、未確認の接続・導入・権限拡張で補わない。

<a id="skl-013"></a>
## 操作と副作用

EMP-009に従い、入力/参照を読む、許可された新規処理コードを保存する、指定先へ新規成果と検査/停止記録を保存する、会話で報告する。各段階の前に入力範囲、出力先、衝突なし、当回の依頼と実権限を確認する。原本変更、既存成果置換、恒久ルールの自動変更、第三者送信/公開、会計更新を実施しない。

各操作を社員AGENTSのEMP-009へ対応させる。作成、既存成果物の置換、恒久変更、第三者送信の条件を混同しない。未確認の操作は開始しない。

<a id="skl-006"></a>
## 手順・判断・停止条件

1. 明示依頼、3パラメータ、入力/参照、実権限を確認する。不足/不正はSKL-010へ進み、まだ成果物を作らない。
2. 入力一覧とhash、CSV構造、日付/必須ID、マスタの一意性と別名対応を点検する。CSV構造不正、日付不正、必須ID欠落、マスタ重複や別名矛盾など構造的に判断不能なら停止する。
3. [判断規則](references/sales-rules.md) の順序に従い、期間で切る前の全販売/返品入力を追跡する。同一IDの完全一致/衝突を区別し、明示別名の正規化、販売の採用/保留、販売日基準価格との比較、返品の元売上照合とグループ超過を判定する。原値を修正しない。
4. 対象期間の両端を含めて販売日/返品日で計上し、期間外も別分類で保持する。売上、返品、純売上、販売/返品/純数量を区別し、月・店舗・商品・カテゴリへ集計する。保留がある数値は照合できた分の暫定値とする。
5. 完全に含まれる隣接月だけで前月比較し、純売上への試験閾値で「確認すべき変化」を示す。価格差と商品寄与は事実として示す。店舗メモは出典付きで併記し、原因や施策を推測しない。
6. 新規runへHTML/JSONと必要な記録を作る。SKL-008の検査を行い、失敗/未決を残す。重大な照合失敗を解消できなければ依存する結果を確定せず停止・引継ぎし、自己検査と人の検収を分けて報告する。

分岐や閾値は確認された業務条件に従う。原本を保持し、手順にない重要な判断は創作せず確認する。

<a id="skl-007"></a>
## 出力

社員workspaceの `outputs/` 直下に、UTC日時＋一意IDのrunディレクトリを新規作成し、`report.html` / `report.json` を保存する。検査/実行/停止記録は `records/runs/` 直下の同じrun-idへ保存する。既存ファイルは置換しない。

HTMLは全店概況、月別推移、店舗比較、増減を作った商品、データ品質/照合保留、根拠行を検索できるパネルを備える。最初に見るべき店舗と保留の影響を伝え、部分月や比較不能を明示する。

JSONは `totals, monthly_store, monthly, by_product, by_category, change_flags, price_mismatches, dispositions, source_refs, self_checks` を持つ。dispositionsには全CSV原行の採用・完全重複・衝突・不明・期間外等の処理分類、file/物理line/ID/原値と理由を残す。マスタも参照資料としての処理状況を追跡し、取引の集計へ混ぜない。必要に応じて用途内のフィールドを補足できる。実行パラメータ、入力一覧/hash、定義版/hash、未解決、`human_acceptance=false`、根拠付きの店舗メモを含める。保留値の影響と集計に入らなかった理由を示す。

成果物はEMP-004の指定先に保存し、根拠・除外条件・未確定箇所・確認待ちを読み取れる形にする。既存ファイルと衝突したら無確認で置換しない。

<a id="skl-008"></a>
## 検証

- 全資料を追跡し、全CSV原行の分類数と入力行数を照合する。重複除外・衝突・不明・期間外の根拠と原値を失わない。
- 原値から金額を再計算し、全体・店舗・月・商品・カテゴリ合計の一致、売上/返品の紐付け、金額/数量の保存を照合する。
- 完全重複は1件だけ、衝突は全行保留、複数返品の超過はグループ保留であることを確認する。
- 返品は実記録の返金額を使い、同日可・前日不可、期間で切る前の元売上照合、返品日の計上を確認する。価格差を基準価格で勝手に補正していないか点検する。
- 前月比較の完全月条件、純売上の10万円かつ20%閾値、前月0円の割合なし、部分月の注意を点検する。因果や良し悪しを創作しない。
- HTML/JSONの表示値一致、根拠参照と原文/行の実在、安全な文字列表示と外部資源非依存を確認する。入力のbefore/after hash一致、既存成果/旧版の保護を確認する。
- 検査方法・対象・結果・未実施を記録する。独立期待値は取りまとめ側で照合するため閲覧しない。

実施した検査と結果を記録し、実施していない検査を成功と報告しない。根拠と出力を照合し、重大な失敗を見栄えや速さで相殺しない。

<a id="skl-009"></a>
## 完了と人への検収依頼

依頼元へ成果物のパス/版、根拠、実施した自己検査と失敗/未実施、保留の影響、未解決と必要な確認を会話で提示する。結果は自己検査済み・検収待ちとして扱い、実際の指定された人の対象版への確認なしにhuman_acceptanceをtrueにしない。予定されたClaude独立レビューも人の検収とは別で、自動で依頼・起動しない。

成果物の場所・版、根拠、検査結果、未解決点を指定された検収者へ提示する。自己検査済みと検収済みを区別する。第三者への送信は別の承認境界に従う。

<a id="skl-010"></a>
## 失敗・中断・再開の引継ぎ

質問前に `records/runs/` 直下の新しいrun-idへ停止記録を保存できるか確認する。記録には手順版runtime-v001と定義hash、不足/不正項目、確認済みの入力と取得できたhash、処理済み/未処理ファイル・行/グループ、未実行工程、部分成果の位置と状態、停止理由、依頼元への確認内容と再開条件を含める。書込み不可なら同内容を会話へ残す。再開時は元停止記録、入力/現行定義/既存成果の版を照合し、別runとして始める。入力や業務条件が変わった範囲を再評価し、二重処理・無確認置換・無制限再試行をしない。

実行時の必須値が不足した確認待ちも、開始前の停止として扱う。質問を返す前に、許可された記録先への新規保存可否を確認し、手順版、不足項目、確認済み入力（ハッシュは取得できた場合のみ）、未実行の処理、再開条件を新しい停止記録へ残す。業務の出力フォルダはまだ作らない。未確認値は理由とともに未確認のままにし、記録を書けない場合は同じ内容を会話に残す。再開時は旧停止記録を参照して新しいrunを開始する。

実行した処理と未実行の処理、部分成果の場所・状態、止まった理由、必要な確認、再開条件を残す。再開前に既存成果物と入力の版を確認し、二重処理・無確認置換・無制限の再試行を避ける。
