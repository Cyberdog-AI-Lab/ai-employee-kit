# 店舗売上の見渡し担当 — 現行ヒアリング

AIが架空の担当者を演じた回答を、現行条件として整理した記録です。意味回答はすべて **proposed（模擬条件）**、通常confirmedは0、人による定義承認・成果検収は未実施です。質問文は読みやすく整理しており、当時の発言の逐語録ではありません。原文・42項目の対応・確認出所は [Gitに保存した回答台帳](https://github.com/Cyberdog-AI-Lab/ai-employee-kit/blob/8ed9ba51a3bf66ab8f8a009e6fbc3551b23394c1/sample/sales/records/runtime-v001/answers.json) で確認できます。

## 誰の、何の仕事か（EMP-001〜003 / SKL-002〜003）

**問い：誰が何を判断できるようにしますか？**

架空のこもれび商店の店長へ、4店舗・3か月の売上・返品・純売上と数量をまとめ、現状、確認すべき変化、根拠行を短時間で把握できる資料を渡す。

依頼者、成果の検収者、定義変更の確認者、保守担当は [AGENTSの役割設定](AGENTS.md#emp-003) に従います。模擬の役割設定を、実際の人が確認した記録にはしません。

## 入力と実行条件（EMP-004〜005 / SKL-004）

**問い：どの資料を使い、毎回何を指定しますか？**

[inputsの架空原本](inputs/README.md) を読取り専用で扱います。入力一式はfixture_revision=v3。次は同梱した最新成果の実行値で、次回の既定値ではありません。新しい依頼で値を明示します。

| パラメータ | 同梱成果の実行値 |
| --- | --- |
| `input_dir` | `inputs` |
| `start_date` | `2026-07-01` |
| `end_date` | `2026-09-30` |

型・検証・不足時の扱いは [Skillの入力条件](.claude/skills/work-001/SKILL.md#skl-004) に従います。日付やIDを入力ファイル・PCの時計から補いません。

## 判断のルール（SKL-006 / SKL-011）

**問い：どこまで自動で判断し、何を推測しませんか？**

マスタに明示された別名だけで対応づける。同一ID・全原値一致は最初の1行を採用し、値が異なる同一IDは全行保留。未知の店舗・商品や不正数値は定義に従って保留し、原値を修正しない。売上は数量×単価−値引き、純売上は採用売上−採用返金。価格基準との差は確認事項にし、実売単価を置き換えない。返品は入力全体の一意な元売上へ結び、累積超過はグループで保留する。

詳細条件は [判断規則](.claude/skills/work-001/references/sales-rules.md)、列・型は [入力構造](.claude/skills/work-001/references/input-schema.md) に残す。返品日は売上日と同日を許し、それより前を保留する。

<a id="threshold"></a>
追加質問「変化判定の10万円・20%は何を基準にするか」への模擬回答は **純売上**。完全に指定期間に含まれる隣接月だけを比較し、絶対金額差10万円以上かつ増減率の絶対値20%以上を示す。前月0円は割合を作らない。原因や良し悪しは推測せず、店舗メモは出典付きの事情として併記する。

## 成果物と確認（EMP-006〜007・013 / SKL-007〜009）

**問い：何を渡し、何を確かめますか？**

単体HTML・JSON を `outputs/<新しいrun-id>/` に保存します。要点・次に確認する事項を先に、日本語で示し、根拠原文・行・IDへ辿れるようにします。入力の前後hash、対象と除外の網羅、形式間の値の一致、業務ごとの検算を確認します。自己検査と人の検収を分け、`human_acceptance: false` を保持します。詳細は [検査手順](.claude/skills/work-001/SKILL.md#skl-008)。

## 停止と操作範囲（EMP-008〜009・012 / SKL-005・010・013）

**問い：何が足りなければ止め、どこへ保存できますか？**

CSV構造・日付・必須IDの不正、マスタ重複や別名矛盾など、構造的に判断不能なら停止する。行ごとの未知値や衝突は保留として根拠と影響を表示する。 必須パラメータ不足・原本保護不能・既存成果の置換が必要な場合も停止します。質問前に新しい `records/runs/<run-id>/` へ理由・未処理・再開条件を記録し、書けなければ会話へ残します。

今回の依頼に必要な入力・定義の読取り、新しいoutputs・実行記録・必要な処理コードの保存に限定します。原本変更、既存成果の置換、外部送信、新規連携・導入・権限拡張は含めません。利用可能なローカル道具と実権限を、その都度確認します。MCPは必須ではありません。

## 引継ぎと未決（EMP-010〜011 / SKL-001・012）

**問い：どの手順を使い、改善をどう残しますか？**

仕事のslugは形式上の固定値 `work-001`。指摘・理由・差分・影響を残し、依頼された範囲で改訂します。過去の定義はGit履歴から回復できます。業務意味はruntime-v001を継承し、今回の整理は保存先と根拠参照の変更です。任意のSKL-012は未回答のままです。実環境の操作権限・次回の実行依頼・人の検収は、新しい利用時に別途確認する事項です。
