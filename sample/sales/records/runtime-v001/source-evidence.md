> SIM-DETAIL-002/sales:

<a id="sales-1"></a>

> 1. マスタに明示された別名だけ正規化し、あいまいな名前を似た商品へ寄せない。商品/店舗のマスタ重複や同じ別名が複数IDへ向く矛盾は全体停止。CSV列: transaction_id,date,store_label,product_label,quantity,unit_price_jpy,discount_jpy,channel。正規化IDはmasterから得る。

<a id="sales-2"></a>

> 2. 同一transaction_id・全原フィールド一致の完全重複は最初の1行だけ採用し、他を重複除外として各出典を残す。決定的な順序は入力相対パス昇順・物理行番号昇順。同じIDで値が異なる場合はグループ全行を保留し、どれかを選ばない。未知の商品/店舗、quantity空欄、不正数値は行を保留。quantity/unit_price_jpy/discount_jpyは非負の整数、discountはqty*price以下。形式不正のCSV/不正日付/必須ID欠落のような構造問題は停止。保留を含む数字は「照合できた分の暫定値」と表示する。

<a id="sales-3"></a>

> 3. 採用売上はquantity*unit_price_jpy-discount_jpy。整数円、税再計算なし。商品ごとに販売日以前で最後のeffective_fromを持つ価格基準と比較する。基準と実販売単価が違っても実記録額で集計し、「価格差・確認対象」とする。基準価格で勝手に直さない。

<a id="sales-4"></a>

> 4. 返品CSVはreturn_id,original_transaction_id,return_date,quantity,refund_jpy,reason。元取引は期間で切る前の入力全体から照合。採用済みの一意な売上へ結べない返品、返品日が売上日以前（同日可）、数量の累計が元売上を超える返品、返金累計が元売上金額を超える返品は保留。複数返品で超過するなら同じ元取引の返品グループを保留して入力順で一部だけ通さない。重複返品IDも販売IDと同じ完全一致/衝突の扱い。既知純売上=採用売上額−採用返金額、純数量=販売数量−返品数量。返品は返品日・元売上の店舗/商品へ計上。

<a id="sales-5"></a>

> 5. start_date/end_dateはISO日付で両端含む、開始<=終了。input_dirは当該W/inputsだけ。期間外は別分類にして、全原行の追跡を残す。複数月を比較するとき、隣接月が両方完全に指定期間に含まれる場合だけ「前月比較」とし、部分月は比較条件の注意を付ける。

<a id="sales-6"></a>

> 6. 「異常」断定ではなく「確認すべき変化」と表示。店舗ごとの前月比について絶対金額差10万円以上かつ増減率の絶対値20%以上を試験用閾値とする。前月0円なら割合を出さず金額差を示す。原因・良し悪しは推測しない。売上/返品/純売上を区別し、商品寄与は増減額の事実だけ。

<a id="sales-7"></a>

> 7. HTML: 全店の概況、月別推移、店舗比較、増減を作った商品、データ品質/照合保留、根拠行を検索できるパネル。最初の画面で見るべき店舗と保留の影響を把握できる。JSON: totals, monthly_store, monthly, by_product, by_category, change_flags, price_mismatches, dispositions（全CSV原行の採用/完全重複/衝突/不明/期間外などとfile/line/ID/原値）, source_refs, self_checks。フィールドは用途に合う補足可。

<a id="sales-8"></a>

> 8. 検査は全行分類数=入力行数、原値再計算と全体/店舗/月/商品合計の一致、売上と返品の照合、金額/数量の保存、閾値表示が定義どおり、価格差が集計額の勝手な補正になっていないこと。独立期待値は取りまとめ側で実行後に照合するので見に行かない。
