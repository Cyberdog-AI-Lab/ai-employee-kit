# 会議引継ぎ担当 — 現行ヒアリング

AIが架空の担当者を演じた回答を、現行条件として整理した記録です。意味回答はすべて **proposed（模擬条件）**、通常confirmedは0、人による定義承認・成果検収は未実施です。質問文は読みやすく整理しており、当時の発言の逐語録ではありません。原文・42項目の対応・確認出所は [Gitに保存した回答台帳](https://github.com/Cyberdog-AI-Lab/ai-employee-kit/blob/8ed9ba51a3bf66ab8f8a009e6fbc3551b23394c1/sample/minutes/records/runtime-v001/answers.json) で確認できます。

## 誰の、何の仕事か（EMP-001〜003 / SKL-002〜003）

**問い：誰が何を判断できるようにしますか？**

架空のこもれび商店の企画責任者へ、体験販売会の現行決定、正式変更、判断待ち、担当別の宿題を根拠付きで引き継ぐ。

依頼者、成果の検収者、定義変更の確認者、保守担当は [AGENTSの役割設定](AGENTS.md#emp-003) に従います。模擬の役割設定を、実際の人が確認した記録にはしません。

## 入力と実行条件（EMP-004〜005 / SKL-004）

**問い：どの資料を使い、毎回何を指定しますか？**

[inputsの架空原本](inputs/README.md) を読取り専用で扱います。入力一式はfixture_revision=v3。次は同梱した最新成果の実行値で、次回の既定値ではありません。新しい依頼で値を明示します。

| パラメータ | 同梱成果の実行値 |
| --- | --- |
| `input_dir` | `inputs` |
| `project_id` | `KOMOREBI-EVENT-2026` |
| `as_of` | `2026-10-15` |

型・検証・不足時の扱いは [Skillの入力条件](.claude/skills/work-002/SKILL.md#skl-004) に従います。日付やIDを入力ファイル・PCの時計から補いません。

## 判断のルール（SKL-006 / SKL-011）

**問い：どこまで自動で判断し、何を推測しませんか？**

企画責任者の明示的な決定・正式変更・取消を、その対象が特定できる範囲だけ採用する。会議日が新しいだけで上書きしない。完了には担当の報告と企画責任者の確認が必要。提案・撤回・決定・取消・完了を分ける。

担当・期限の矛盾や未定はnullと根拠付き候補を残す。「それ」など対象不明の発言を近くの宿題へ割り当てない。旧案内が残っていても正式な決定を戻さない。具体的手順は [Skillの判断手順](.claude/skills/work-002/SKILL.md#skl-006)、入力は [入力契約](.claude/skills/work-002/references/input-contract.md) に残す。

## 成果物と確認（EMP-006〜007・013 / SKL-007〜009）

**問い：何を渡し、何を確かめますか？**

HTML・JSON・印刷向けMarkdown を `outputs/<新しいrun-id>/` に保存します。要点・次に確認する事項を先に、日本語で示し、根拠原文・行・IDへ辿れるようにします。入力の前後hash、対象と除外の網羅、形式間の値の一致、業務ごとの検算を確認します。自己検査と人の検収を分け、`human_acceptance: false` を保持します。詳細は [検査手順](.claude/skills/work-002/SKILL.md#skl-008)。

## 停止と操作範囲（EMP-008〜009・012 / SKL-005・010・013）

**問い：何が足りなければ止め、どこへ保存できますか？**

案件違い、ID/日付不正・重複、資料読取不能、必要構造不正なら停止する。担当や期限の不明・矛盾はnullと候補を残し、独立して整理できる範囲を進める。 必須パラメータ不足・原本保護不能・既存成果の置換が必要な場合も停止します。質問前に新しい `records/runs/<run-id>/` へ理由・未処理・再開条件を記録し、書けなければ会話へ残します。

今回の依頼に必要な入力・定義の読取り、新しいoutputs・実行記録・必要な処理コードの保存に限定します。原本変更、既存成果の置換、外部送信、新規連携・導入・権限拡張は含めません。利用可能なローカル道具と実権限を、その都度確認します。MCPは必須ではありません。

## 引継ぎと未決（EMP-010〜011 / SKL-001・012）

**問い：どの手順を使い、改善をどう残しますか？**

仕事のslugは形式上の固定値 `work-002`。指摘・理由・差分・影響を残し、依頼された範囲で改訂します。過去の定義はGit履歴から回復できます。業務意味はruntime-v001を継承し、今回の整理は保存先と根拠参照の変更です。任意のSKL-012は未回答のままです。実環境の操作権限・次回の実行依頼・人の検収は、新しい利用時に別途確認する事項です。
